EasyCGTree 5.0 - changes compared with version 4.2
===================================================

Version 4.2 (2024) is the last published version before 5.0. This file lists what is new, what works
differently and what was fixed. (中文说明见后半部分。)


1. New features
---------------
- Graphical interface EasyCGTree_GUI 1.0 for Windows, Linux and macOS: all options of the five scripts,
  the commands it runs (to copy into a terminal), the run log, the status of the analysis and a file view.
- macOS support. Ready-to-use packages for Windows, Linux and macOS (Apple silicon and Intel), with the
  third-party programs. One set of scripts for all systems (v4.2 had separate Windows and Linux versions).
- The scripts can be called from any directory, and the input directory can be anywhere (also paths with
  spaces). '-outdir' writes all results to a chosen directory (all five scripts).
- New task 'predict' (CDS prediction). '-task hmmsearch' reuses an existing prediction, so several HMM sets
  can be tried without predicting the CDS again.
- Trees from nucleotide alignments of the core genes: '-seq nucl' (all genomes as DNA sequences);
  '-keep_CDS_nucl' keeps the CDS DNA sequences of a protein-based run for later use.
- NCBI annotation files as input: protein ('translated_cds.faa') and CDS ('cds_from_genomic.fna') files of
  one assembly are paired by locus_tag, so no CDS prediction is needed.
- '-dry_run' shows how the input files will be grouped and named, without running anything.
- Record of the analysis ('<input>_TEM/EasyCGTree_record.txt'): later tasks check that their settings fit
  the earlier results (e.g. the same HMM set) and use the recorded settings by default.
- trimAl: new value '-trim nogaps'. A gene without any column left after trimming is skipped with a warning.
- Result files are not overwritten: an existing tree or table with the same name is renamed to
  '<file>.<date>.bak'.
- New script EasyCGTree_SNP.pl: core-genome SNPs from the nucleotide alignments of the core genes, SNP
  positions (also in a reference genome), pairwise SNP distances and a SNP tree (IQ-TREE or FastTree).
  Missing EasyCGTree results are produced automatically.
- New script EasyCGTree_SpecificSNP.pl: numbers of strain- and clade-specific SNPs on the SNP tree or on any
  other tree, with rooting by an outgroup and tables of the positions.
- Gene_Prevelence.pl: tables of copy numbers, a summary per gene and per genome, a preview of how many genomes
  and genes pass '-genome_cutoff'/'-gene_cutoff', and a table of genes whose best hits are the same protein
  in some genomes (such proteins are marked with '*' in the tables).
- BuildHMM.pl: options '-name' (name of the HMM set), '-force' (overwrite), '-super5' and '-outdir'; all
  input files are checked first; a summary table per gene; the finished HMM set is tested with hmmsearch.


2. Changes in behaviour
-----------------------
- Consensus tree ('-tree cs'): built by IQ-TREE ('-con', extended majority rule) instead of consenseM, which
  is no longer needed. The renaming of the genomes for this step (SPE10001 ...) was removed.
- MUSCLE in the main pipeline: '-align' is used when fewer than 200 genomes passed the screening, '-super5'
  otherwise. (v4.2 compared the number of genes, not genomes, with 200.)
- IQ-TREE results: the best-fit model, log-likelihood and BIC are read from the IQ-TREE report (.iqtree),
  which works with IQ-TREE 2 and 3.
- Default number of threads: 4 (v4.2: 2). A value larger than the number of CPU cores is reduced to it.
- The profile HMM sets are not included in the packages any more; each set is downloaded separately from the
  folder 'HMM' of the repository (GitHub or Gitee). Missing sets are reported with the download links.
- Working directory: the CDS are in 'TEM0_CDS' (v4.2: 'TEM0_Proteome').
- Third-party programs:
      Program     v4.2                        v5.0
      HMMER       3.0                         3.4
      Prodigal    2.6.3                       2.6.3
      MUSCLE      5.1                         5.3
      trimAl      1.4                         1.5.1
      FastTree    2.1.11                      2.2.0
      IQ-TREE     2.2.0 (iqtree2)             3.1.4 (iqtree3)
      ASTRAL      astral-weighted 1.15        wASTRAL of ASTER 1.25 (file name 'astral-weighted')
  HMM sets built with HMMER 3.1 or newer cannot be read by HMMER 3.0: 'hmmbuild' and 'hmmsearch' in 'bin'
  must be of the same version.
- License: GNU General Public License v3.0.


3. Fixes
--------
- Genomes in lower-case letters were taken as protein sequences (only upper-case A/C/G/T were counted).
  Sequences are now converted to upper case, and Windows line ends are removed.
- Missing or incomplete tree files, and programs that fail or are killed (e.g. out of memory), now stop the run
  at once with a clear message; the exit codes of all programs are checked.
- Consensus trees: the old renaming used substring replacement, so names such as 'X-1' and 'X-11' could be
  mixed up.
- BuildHMM.pl (Linux): MUSCLE was called as the Windows program 'muscle.exe' with MUSCLE 3 options, so gene
  families that needed an alignment failed. The input files are no longer renamed.
- Gene_Prevelence.pl: without '-hmm', the results were named after the HMM 'Unknown', and existing search
  results of another HMM set could be used under the wrong name.
- '-gene_cutoff' accepted any value (the range check was wrong).
- Gene names containing '_' (e.g. in custom HMM sets) were cut.
- Hidden files (e.g. macOS '.DS_Store') and sub-directories in the input directory are ignored; two input files
  that would get the same name are reported instead of overwritten.
- The running time was wrong for runs across days or months.
- Only core Perl modules are used (no 'smartmatch', which recent Perl versions removed).


4. Compatibility
----------------
- The options of v4.2 work as before. Working directories made by v4.2 can still be used by the later tasks
  (with a warning, because they have no record).
- Advanced use (mainly for EasyCGTree_GUI): '-options_json' prints the options of a script; the environment
  variables ECG_BIN and ECG_<PROGRAM> (e.g. ECG_IQTREE3) set other locations for 'bin' and the programs.


======================================================================================================

EasyCGTree 5.0 与 4.2 版相比的变化
=================================

4.2 版（2024 年）是 5.0 之前最后一个公开发布的版本。以下列出新增功能、行为变化和问题修复。


1. 新增功能
-----------
- 图形界面 EasyCGTree_GUI 1.0（Windows、Linux、macOS）：可设置五个脚本的全部参数，显示将运行的命令（可复制到终端）、
  运行日志、分析状态和文件浏览。
- 支持 macOS。为 Windows、Linux 和 macOS（Apple 芯片和 Intel）提供可直接使用的软件包，含第三方程序。
  所有系统使用同一套脚本（4.2 版的 Windows 和 Linux 版本是分开的）。
- 脚本可在任意目录下调用，输入文件夹也可位于任意位置（路径可含空格）。'-outdir' 可把全部结果写入指定文件夹（五个脚本均支持）。
- 新任务 'predict'（CDS 预测）。'-task hmmsearch' 会使用已有的预测结果，可在不重复预测的情况下尝试多个 HMM 集。
- 基于核心基因的核酸比对建树：'-seq nucl'（所有基因组须为 DNA 序列）；'-keep_CDS_nucl' 可在基于蛋白的分析中保留
  CDS 核酸序列，供以后使用。
- 可直接输入 NCBI 注释文件：同一组装的蛋白文件（translated_cds.faa）和 CDS 文件（cds_from_genomic.fna）按
  locus_tag 配对，无需预测 CDS。
- '-dry_run'：只显示输入文件将如何分组和命名，不运行任何程序。
- 分析记录（'<input>_TEM/EasyCGTree_record.txt'）：后续任务会检查设置是否与前面的结果一致（如是否为同一个 HMM 集），
  并默认沿用记录中的设置。
- trimAl 新增 '-trim nogaps'。修剪后不剩任何列的基因会被跳过，并给出警告。
- 不覆盖结果文件：已有的同名树或表格会改名为 '<文件名>.<日期>.bak'。
- 新脚本 EasyCGTree_SNP.pl：从核心基因的核酸比对中提取核心基因组 SNP，给出 SNP 位置（也可给出在参考基因组中的位置）、
  两两之间的 SNP 距离，并构建 SNP 树（IQ-TREE 或 FastTree）。缺少的 EasyCGTree 结果会自动生成。
- 新脚本 EasyCGTree_SpecificSNP.pl：在 SNP 树或其他树上统计菌株和分支特异的 SNP 数目，可用外群定根，并给出各位点的表格。
- Gene_Prevelence.pl：新增拷贝数表、按基因和按基因组的汇总表、在给定 '-genome_cutoff'/'-gene_cutoff' 下能通过筛选的
  基因组和基因数的预览，以及在部分基因组中最佳命中为同一蛋白的基因对表（表中用 '*' 标出这类蛋白）。
- BuildHMM.pl：新增 '-name'（HMM 集名称）、'-force'（覆盖）、'-super5' 和 '-outdir' 选项；运行前检查所有输入文件；
  输出各基因的汇总表；构建完成后用 hmmsearch 检验 HMM 集。


2. 行为变化
-----------
- 一致树（'-tree cs'）改由 IQ-TREE 构建（'-con'，扩展多数一致规则），不再需要 consenseM；该步骤中对基因组的重命名
  （SPE10001 ……）已取消。
- 主流程中的 MUSCLE：通过筛选的基因组少于 200 个时用 '-align'，否则用 '-super5'。（4.2 版用于与 200 比较的是基因数，
  而不是基因组数。）
- IQ-TREE 结果：最优模型、对数似然值和 BIC 从 IQ-TREE 报告文件（.iqtree）中读取，适用于 IQ-TREE 2 和 3。
- 默认线程数为 4（4.2 版为 2）；超过 CPU 核心数时按核心数运行。
- 软件包中不再包含 profile HMM 集，需从仓库（GitHub 或 Gitee）的 'HMM' 文件夹单独下载；缺少时会给出下载链接。
- 工作目录中 CDS 所在的文件夹为 'TEM0_CDS'（4.2 版为 'TEM0_Proteome'）。
- 第三方程序：
      程序        4.2 版                      5.0 版
      HMMER       3.0                         3.4
      Prodigal    2.6.3                       2.6.3
      MUSCLE      5.1                         5.3
      trimAl      1.4                         1.5.1
      FastTree    2.1.11                      2.2.0
      IQ-TREE     2.2.0（iqtree2）             3.1.4（iqtree3）
      ASTRAL      astral-weighted 1.15        ASTER 1.25 中的 wASTRAL（文件名为 astral-weighted）
  HMMER 3.1 及以上版本构建的 HMM 集不能被 HMMER 3.0 读取：'bin' 中的 hmmbuild 和 hmmsearch 必须为同一版本。
- 许可证：GNU 通用公共许可证第 3 版（GPL-3.0）。


3. 问题修复
-----------
- 小写字母的基因组会被误判为蛋白序列（只统计了大写的 A/C/G/T）。现在序列会先转为大写，并去掉 Windows 换行符。
- 树文件缺失或不完整，或程序运行失败、被终止（如内存不足）时，会立即停止并给出明确提示；所有程序的退出码都会检查。
- 一致树：原来的重命名采用子串替换，'X-1' 和 'X-11' 这类名称可能被混淆。
- BuildHMM.pl（Linux）：调用的是 Windows 程序 'muscle.exe'，且使用 MUSCLE 3 的参数，需要比对的基因家族会运行失败。
  输入文件也不再被改名。
- Gene_Prevelence.pl：不指定 '-hmm' 时，结果以 'Unknown' 命名，且可能把另一个 HMM 集的已有检索结果当作当前 HMM 集的结果。
- '-gene_cutoff' 的取值范围检查有误，任何值都会被接受。
- 含 '_' 的基因名（如自定义 HMM 集中的）会被截断。
- 输入文件夹中的隐藏文件（如 macOS 的 '.DS_Store'）和子文件夹会被忽略；两个输入文件改名后重名时会报错，而不是互相覆盖。
- 跨天或跨月运行时，运行时间计算错误。
- 只使用 Perl 核心模块（不再使用新版 Perl 已删除的 smartmatch）。


4. 兼容性
---------
- 4.2 版的参数用法不变。4.2 版生成的工作目录仍可用于后续任务（因没有分析记录，会给出提示）。
- 高级用法（主要供 EasyCGTree_GUI 使用）：'-options_json' 输出脚本的参数说明；环境变量 ECG_BIN 和 ECG_<程序名>
  （如 ECG_IQTREE3）可指定 'bin' 和各程序的其他位置。
